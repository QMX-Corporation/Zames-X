# Code of Conduct - Zames-X Game Engine

## 🛑 OUR STANDARDS & ENFORCEMENT
The QMX Corporation cluster operates under a strict technical meritocracy model. Our primary code of conduct is the pursuit of absolute computational efficiency, hardware purism, and execution latency optimization. 

### 1. Expected Technical Behavior
- **Low-Level Precision:** All technical communication inside issues, pull requests, and authorized community channels must focus strictly on factual, reproducible hardware metrics, pipeline optimizations, and HolyC compilation mechanics.
- **Respect for the Core Architecture:** Contributors must respect the BDFL governance model and the structural constraints established to protect the engine against feature creep and academical abstractions.

### 2. Unacceptable Behavior & Abuse Rules
- **Abstractions Violations:** Attempting to force heavy web frameworks, bloated runtime layers, or object-oriented design patterns that invalidate L1/L2 caches into the freestanding codebase is strictly banned.
- **PR Flooding:** Opening unoptimized, incomplete, or useless Pull Requests ("Unnecessary-PRs") that do not actively fix a defect or optimize code processing parameters.
- **Academic Arrogance:** Dismissing practical bare-metal architectures based on obsolete university book concepts or generic textbook rules.

## 👑 CONSEQUENCES & DISCIPLINARY ACTIONS
The Project Administrator (BDFL) holds sovereign, absolute power to moderate all interactions across the repository infrastructure:

* **First Offense (Feature Creep / Bad Code):** Immediate cancellation and closure of the pull request or tracking ticket with a technical warning.
* **Second Offense (Abuse / Public Spam):** Temporary suspension of repository interaction flags and exclusion from the official communication channels.
* **Third Offense (Glowie Behavior / Malicious Spreading):** Permanent ban from the QMX Corporation organization cluster without review or pity.
