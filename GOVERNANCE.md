# Project Governance - Zames-X Game Engine

The Zames-X project operates under a Benevolent Dictator for Life (BDFL) governance model to enforce structural efficiency, prevent feature creep, and protect the core low-level HolyC rendering pipeline from unnecessary abstractions.

## 👑 The Benevolent Dictator for Life (BDFL)
The ultimate authority on all design choices, pull requests, architectural modifications, and code style validation resides with the project founder:

* **dev12124**, dev brazilian, João Guilherme da Silva Freitas Lima <joaoanandalima@gmail.com>

The BDFL holds full executive veto power over any patch or issue submitted to the QMX Corporation cluster. No architectural rewrite, shader parsing modification, or engine deployment can bypass strict BDFL review.

## 📑 Core Principles
1. **Absolute Technical Meritocracy:** Contributions are evaluated strictly on efficiency, cycle-of-clock optimizations, and lack of bloatware. Academical abstractions are explicitly rejected.
2. **Centralized Architectural Control:** While global collaboration is encouraged, the roadmap, development standards, and structural guidelines are dictated top-down by the Project Administrator.
3. **Strict Compliance Over Legacy:** Any code containing compatibility flags for broken historical systems or unoptimized structures will be immediately rejected and canceled at the PR stage.

## 🚀 Decision Making & Conflict Resolution
In the event of technical disagreements regarding core engine implementation (such as pixel mapping syntax or global state synchronization constraints), the BDFL will deliver the final, binding decision. The project does not operate under a democratic voting mechanism.
